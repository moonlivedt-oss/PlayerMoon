# PlayerMoon: анимации интерфейса

Справочник для переноса макета `mockup/index.html` на C++20 + Direct2D/DirectComposition.
Все длительности и кривые берутся из `theme.json` (группы `duration`, `easing`, `spring`, `effect`),
здесь указаны имена ключей и значения в виде «стекло / неон / минимал».

## Кривые

| Ключ | Стекло | Неон | Минимал | Где используется |
|---|---|---|---|---|
| `easing.out` | cubic-bezier(0.22, 1, 0.36, 1) | cubic-bezier(0.16, 1, 0.3, 1) | cubic-bezier(0.25, 0.8, 0.25, 1) | появление, перемещение, ресайз |
| `easing.in` | cubic-bezier(0.4, 0, 1, 1) | cubic-bezier(0.5, 0, 0.75, 0) | cubic-bezier(0.4, 0, 0.6, 1) | уход элемента (старая обложка, старый текст) |
| `easing.spring` | k=420, c=26 | k=380, c=20 | k=300, c=30 | масштаб кнопок, ручки ползунков, точки-индикаторы |

Пружина: масса 1, жёсткость `spring.stiffness` (k), демпфирование `spring.damping` (c).
x(t) = 1 - e^(-z*w*t) * (cos(wd*t) + (z*w/wd) * sin(wd*t)), где w = sqrt(k), z = c / (2*w), wd = w * sqrt(1 - z^2).
В макете пружина задана выборкой (`easing.spring.samples`, 29 точек на 350 мс, у минимала 25 точек на 320 мс);
в C++ лучше считать формулу напрямую. Перелёт: стекло около 7.6%, неон около 15%, минимал около 0.1%.

## Морфинг play/pause

Иконка в сетке 24x24, два четырёхугольника по 4 точки, порядок точек: верх-лево, верх-право, низ-право, низ-лево.

| Фигура | Play (треугольник, разрезан по x=14) | Pause (две полоски) |
|---|---|---|
| A | (8.5,5) (14,8.5) (14,15.5) (8.5,19) | (6.5,5) (10,5) (10,19) (6.5,19) |
| B | (14,8.5) (19.5,12) (19.5,12) (14,15.5) | (14,5) (17.5,5) (17.5,19) (14,19) |

Каждая точка интерполируется линейно с кривой `easing.out` за `duration.base`. Углы скругляются обводкой 1.6 тем же цветом
(в D2D: заливка + DrawGeometry со скруглённым stroke style).

## Правило «ноль кадров в покое»

- Один общий цикл кадров (в макете - `requestAnimationFrame`, в C++ - тик DirectComposition/таймер на vsync).
- Цикл запрашивает следующий кадр, только если кто-то из участников вернул «занят»: идёт воспроизведение,
  полосы визуализатора ещё не опустились, бегущая строка не доехала до шва.
- Музыка на паузе, полосы на нуле, строка на месте -> следующий кадр не запрашивается вообще.
  Любое действие (клик, наведение, смена трека) снова будит цикл.
- Наведение, нажатие и переходы панелей в макете сделаны CSS-переходами; в C++ это анимации DirectComposition
  (IDCompositionAnimation), которые не требуют кадров от приложения.
- Индикатор «Цикл кадров» на странице макета показывает состояние и общий счёт кадров.

## Сокращённые анимации

Включаются системной настройкой (в Windows: «Эффекты анимации» выкл., `SPI_GETCLIENTAREAANIMATION`)
или флажком на странице макета. Тогда:

- все масштабы и сдвиги отключены (`hover-scale` = `press-scale` = 1, `text-shift` = 0, вращение пластинки = 0);
- смена обложки и текста - только затухание 100-120 мс;
- изменение размера окна мгновенное, пружина заменена линейной кривой;
- бегущей строки нет: длинное название обрезается многоточием;
- лесенки в плейлисте и анимации эквалайзера нет;
- визуализатор продолжает работать: это содержимое, а не украшение.
